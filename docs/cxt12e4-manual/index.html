Xbox · 本层默认映射

操作普通操作按住 RT

LT 按住精细移动；Menu ≡ 短按打开任务 / 会话选择，长按约 0.85 秒暂停或恢复手柄。A / B / 方向键在选择面板内用于确认 / 取消 / 选择。

八层默认统一：X 左键 / 按住拖拽，Y 右键，A 回车确认，B Esc。Codex 层按下右摇杆 R3 发送 Tab，RT + R3 为中键；其他层 R3 仍为中键。A 发送 Enter，具体作用取决于前台应用；在终端会执行当前输入。RT + L3 执行本层专用动作，L3 单按仍打开本层设置。Xbox、View、Share 保留系统用途；当前 XInput 接口不接管这些键。普通切窗或切层会保留已经开始的拖拽；摇杆模式改变后须先回中。断连、休眠、暂停或修改配置会释放已按住的鼠标键；恢复时先松开按钮、扳机并让摇杆回中。

终端层 RT+A / B 使用 Ctrl+Shift+C / V；RT+X 进入 copy-mode，RT+Y 暂存 / 恢复输入。L6 使用 Total Commander。层颜色与数字仍显示在 Bridge 托盘，12E4 状态灯保持原有用途。

Windows 分层设置、保存与恢复
  1. 右键托盘 Bridge → 分层按键设置… → 选择 12E4 键盘 或 Xbox 手柄，再选 L1–L8。两设备共用当前层，但各自的映射互不覆盖。
  2. 12E4 可改 12 个键的短按与 4 个旋钮的三个动作；全局任务 / tmux 长按及键12应用组合保持固定。Xbox 可改两个摇杆、ABXY、十字键、LB / RB、L3 / R3 及 RT 组合；LT 精细移动与 Menu 短 / 长按固定。
  3. 切设备、切层、导入和恢复本层默认都先修改草稿，点击保存并关闭才应用；取消保留原配置。导出可保存当前草稿，导入只接受 Windows 格式，不能直接导入 Mac 配置。
  4. 升级已有配置：保留所有已存映射；旧文件若写入旧版 A / B / X / Y，仍会优先于新默认。可逐个改成 A 回车、B Esc、X 左键、Y 右键，并把本层专用动作放到 RT+L3。“恢复本层默认”会重置整个当前设备当前层，包括其他自定义项；最后点“保存并关闭”应用。
  5. “Xbox 参数与暂停应用”可调死区、鼠标速度、滚轮速度、LT 倍率及方向。Windows 滚动速度按滚轮单位 / 秒计，120 单位 = 1 格；Mac 按像素滚动，不宜直接照搬数值。
  6. 配置位于 %LOCALAPPDATA%\Cxt1024Bridge\profiles.windows.json，上一版保存在 profiles.windows.previous.json。坏配置会保留原文件、键盘回到默认映射、Xbox 暂停；不会改写键盘固件。
Menu 选择面板、暂停与游戏
  • Menu ≡ 短按打开 Codex 最近任务 / tmux 已有会话两组列表；LB / RB 切组，十字键选择，A 确认，B 或 Menu 取消。使用打开面板时的稳定任务 / 会话身份；不会创建新 session。切去其他应用会取消面板，避免在后台误选。
  • Menu 长按约 0.85 秒或托盘“暂停 / 恢复 Xbox”只暂停手柄。每次断连、休眠、暂停或修改配置后，先松开按钮、扳机，让两个摇杆回中，再开始操作。
  • 手柄输入非独占，游戏仍会收到原始按键。玩游戏前手动暂停，或用“在当前应用暂停 / 恢复 Xbox”加入实际游戏进程；设置中每行一个进程名，大小写不敏感，可带 .exe，不填写路径。
  • 默认暂停名单只含 Steam、GameBar、GameBarFTServer，不代表已识别 Steam 启动的游戏。处于暂停进程时连 Menu 也不执行 Bridge 操作；恢复请离开该应用或用托盘。Xbox、View、Share 由系统处理。
  • 普通跨窗口拖拽保留已按住的鼠标键；摇杆模式改变后先回中。设置窗口不会执行原应用的键盘映射；Menu 不会关闭未保存草稿。

Windows 实测 · 按顺序确认

Windows 版本已有编译和纯状态回归；原生 Windows 运行、蓝牙设备与各应用操作尚待实机验收。

先确认连接，再测鼠标与分层
  1. 连接与回中：在 Windows 蓝牙设置中连接 Xbox 手柄，按 Xbox 键唤醒；松开所有按钮、扳机和摇杆。托盘菜单应显示 Xbox 已连接。若显示暂停，先在普通应用中从托盘恢复。
  2. 鼠标：在空白页面移动左摇杆，按住 LT 后应明显变慢；X 单击链接，按住 X 拖动一个可移动窗口，再松开确认拖拽结束。Y 应打开右键菜单，B 应发出 Esc；在安全的测试对话框中用 A 确认。
  3. 滚动与选择：在较长网页上推右摇杆上下滚动；短按 Menu 应打开列表，LB / RB 切组，B 关闭。先只取消，不选没有确认的项目。
  4. 暂停：在普通应用中长按 Menu 约 0.85 秒，鼠标与快捷键应停止；再次长按恢复，释放所有输入后再移动摇杆。
  5. 应用层：分别切到 Codex、Windows Terminal、Notion，观察托盘数字变为 1、2、3。Codex 的 RT+L3 聚焦输入框，按下右摇杆 R3 发送 Tab，RT+R3 保留中键；Notion 的 RT+L3 打开快速搜索。X / Y 的鼠标功能和 A / B 的确认 / 取消在全部八层保持一致。
  6. 已有 tmux：只在已有 session 中测试 RT+L3 缩放 pane，RT+十字键切 pane，RT+LB / RB 切已有 session。RT+X 进 copy-mode，RT+Y 暂存 / 恢复输入；菜单确认后会话总数不应增加。RT+A / B 是终端复制 / 粘贴，先使用无执行风险的短文本，不自动发送回车。
  7. 保存与隔离：把 Xbox 某层的一个按钮临时设为“不执行动作”，保存并关闭；该按钮应仅在该层停用，12E4 同层不受影响。再恢复本层默认并保存。记录失败时的应用、层号、按钮、预期与实际结果，便于对照日志。

ChatGPT 六任务状态灯

所有层中，键1、2、3、5、6、7始终对应任务1–6并显示实时状态；当前层指示灯另外叠加显示。

白色 · 空闲 / 已查看任务没有未处理状态。
深蓝动态 · 思考中亮度流动/闪烁，表示任务正在运行。
深绿色 · 已完成新结果尚未查看；打开任务后恢复白色。
琥珀黄 · 等待输入任务暂停，正在等你的回答或操作。
红色 · 出错任务出现错误，需要打开检查。

运行规则与排错

忘记行为时先看下面几项。

自动切层与手动覆盖
  • 托盘“使用说明（Windows / Mac）”打开此域名下的 Windows 手册，可从顶部切换到 Mac；“快捷键总表”打开 新域名首页。下载源码中的 docs/cxt12e4-manual/index.html 也可直接在浏览器离线打开。快捷键总表记录维护者的 Mac 配置，不是 Windows Bridge 的默认键位。
  • Bridge 根据前台进程自动选择专用层；L5“3D建模 / Blender”只精确匹配 blender.exe。浏览器和未匹配应用统一进入 L8“通用 / 浏览器”，全层固定绑定，没有浏览器子配置。用户只看到L1–L8，内部索引0和手册 ?layer=0 仍兼容显示L8。
  • 新电脑不能只插键盘：从 项目仓库取得默认 main 分支源码后运行 install\windows-home\Install-Cxt12E4Bridge.ps1。安装器先本机编译和自测，再备份旧版、安装用户级 Bridge、设置开机启动并验证唯一进程；使用tmux与Agent状态灯时增加 -InstallWslIntegrations。它不刷固件，也不携带凭据或当前电脑的私人配置。
  • Windows Terminal 自动进入 L2，但程序无法判断当前标签是否真的在运行 tmux；必要时可手动切层。
  • 键12组合用于打开或切换 Windows 任务栏应用；应用成为前台窗口后，Bridge 会自然切到对应层。
  • 托盘菜单可按 L1–L8 顺序直接手选；手选层保持到前台窗口发生变化，再恢复自动判断。键12长按现统一用于 tmux session 04，不再回 L8。
  • L1–L8 中，任务灯键1、2、3、5、6、7按住650ms切换并聚焦 ChatGPT任务1–6；Bridge 会在深链接前激活 ChatGPT，之后复核实际前台窗口并重试，避免只闪任务栏却仍停在tmux。session灯键9、10、11、12、8、4按住650ms切换最活跃tmux客户端到当前存在的session 01–06，并优先把最近使用的Windows Terminal窗口拉到前台。session不存在时不切换、不抢焦点。短按只执行当前层功能；组合键优先取消长按。
  • 旋钮按压松开后执行一次；窗口进度标题更新不再取消650ms长按。快速旋转过期的旧动作不回放；请独立操作旋钮，检测到与其他键同码重叠时会取消，全部松开后重试。私有右Ctrl标记仍经过系统，Listary的双Ctrl开关仍需单独关闭。
  • 托盘“退出”会同时停止watchdog，不再自动拉起；KBT不参与自动切层，也不需要后台运行。
Codex 官方接口与自动回退
  • Bridge 优先通过官方 Codex App Server 的稳定 stdio JSONL 接口调用 thread/list，获取任务 ID、标题、顺序与 rollout 路径。
  • 本机只读验证中，官方接口前12个线程与原本地目录 12/12 ID 一致；接口不可用时自动回退到只读本地目录，30秒后重试。
  • ChatGPT 桌面应用使用另一 App Server 进程，独立连接会把桌面线程报告为 notLoaded，所以实时蓝/绿/黄/红任务灯继续读取双方共享的 rollout 事件日志。
  • 任务聚焦、语音与界面工具仍使用深链、UI Automation 和现有快捷键；本阶段的官方接口接入严格只读，不会启动、恢复、分叉、中断或修改任务。
  • 诊断命令：Cxt12E4Bridge.exe --codex-app-server-probe。Codex CLI 不在默认目录时，可设置 CXT_CODEX_PATH。
统一长按与短按
  • K4 在 L1–L8 旋转时统一发送连续加速、无修饰键的纵向滚轮，各层只保留不同的按下功能；Blender的3D视图将滚轮解释为缩放，面板通常用于滚动，不是绕视角。Bridge 会先等待旋钮私有触发码的右 Ctrl 标记松开，再发送滚轮，避免浏览器误触 Ctrl+滚轮缩放。
  • 键9保留各层短按语义：L1显示／隐藏左侧栏；L2暂存或恢复Agent未发送输入；L5撤销；L8新标签；其他层保持原功能。长按始终进入tmux session 01。
  • L4与L7键9短按仍分别关闭笔记、清空输入；长按统一进入tmux session 01，不再打开旧命令面板或上下文菜单。
  • L5键4短按旋转 R，L8键4短按重做 Ctrl+Y；长按均只进入tmux session 06。浏览器刷新已放到L8的K4按下 F5。
  • K12任务栏组合必须始终停留在键12按下时的同一前台窗口、层和上下文；中途切换窗口会取消组合。键12长按动作已经触发后，再补按功能键也不会追加第二个组合动作。L1键4组合已删除。
灯光与硬件备注
  • Windows全局键盘和鼠标连续40分钟没有输入时，Bridge会暂停灯光心跳，固件随后熄灭全部12颗灯；下一次真实键鼠输入后自动恢复当前任务、tmux和层提示状态，不影响快捷键。
  • Bridge 心跳中断约 3 秒后，固件会熄灭所有灯，避免保留错误状态。
  • 输入接收、日志和状态镜像已分开运行；输入钩子每10秒自动刷新。若再次出现“灯亮但按键无效”或短暂全灭，请保留发生时间，日志会记录输入收发与心跳延迟，便于定位。
  • Windows 通知区的当前层图标使用铺满画布的高对比方形色块和最大化数字；亮色层自动显示黑字，暗色层自动显示白字，比旧版小圆图标更醒目。
  • 12颗灯同时纯白诊断：运行 Cxt12E4Bridge.exe --all-light-test-white 15；测试结束后恢复实时灯光，不写固件或 EEPROM。
  • 所有层从底排左侧开始，键9、10、11、12、8、4依次对应 tmux session 01–06；L1–L8依次在键1–8短暂双呼吸，平时仍显示任务或 session 状态。深蓝运行态继续做亮度流动。
  • Bridge 读取实时 tmux pane/session 清单，以session ID、创建时间和server PID区分同名重建会话；pane编号复用或tmux重启不会再让4–6号灯串位。同一01–06编号同时存在多个session时，对应灯熄灭且长按拒绝切换。WSL传输超时或异常不再等同于session消失：已有可信清单时继续显示最后一次已验证状态，并按2秒逐步退避到最多60秒重试；只有tmux明确报告no-server才清灯。Bridge重启后仅在同一次Windows启动内使用最长1小时的严格清单缓存，跨系统重启、过期或损坏缓存均拒绝；缓存只续显灯光，长按切换仍须实时确认session。任意层长按灯位在WSL内紧邻switch-client取得同源revision截点：切换前已有完成确认成白色，切入后才完成仍锁绿。外部tmux切换没有可靠的先后事件，因此不会自动清绿，请用灯位长按完成“切回并确认”。即使thinking→completed整轮夹在两次轮询之间，新revision也不会漏掉。
  • OpenCode 与 Claude Code 使用各自的官方插件/hooks事件上报状态；Claude被用户中断时以其后续idle_prompt通知恢复白色，专用过滤器不会误处理Grok输入，并只在原状态仍为运行/等待时写idle，不会覆盖正常Stop已经写入的completed绿灯；Grok专有hooks独立放在其hooks目录，不污染Claude设置。Grok在计划批准或权限放行后，一旦继续调用工具，会把同一pane遗留的黄色等待态恢复为蓝色运行态；其他pane若确实仍在等待，session仍保持黄色。已有进程需要在/hooks中重载或重启一次才会加载新上报器。
  • 两把键盘均已同步 v11 固件：第一把于 2026-08-25 刷入，第二把于 2026-08-26 刷入。v11 保留 ChatGPT 与 tmux 两组六灯及深蓝运行呼吸，并把 tmux session 01–06 的灯位改为键9、10、11、12、8、4；用户可见的L1–L8仍按键1–8顺序做醒目的双呼吸层提示，L8在固件协议内部仍使用索引0。两次刷写的 DFU 内置校验均通过；第二把又独立读回完整 28,672 字节应用区，与源镜像逐字节一致，重新枚举后的 Raw HID 协议1探测通过。
  • 键2绿通道曾出现间歇性失效：白色会暂时表现为粉色，随后可能恢复。这是灯珠硬件问题，不是任务状态。
  • 键10红通道测试异常，因此 L6 使用不依赖红通道的冰蓝色，L7 使用绿色。
  • 灯珠型号确认为 SK6812MINI-E：3228 封装、5V、四脚侧翼；更换时优先选 12mA 版本，并再次核对缺口方向和焊盘定义。
